# RAG 检索聊天页实现计划

> **面向代理式执行者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans，按任务逐步实现本计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 新增 `/chat` RAG 聊天页：LangChain + Milvus 检索题库与上传文档，PostgreSQL 持久化会话/消息/文档元数据，SSE 流式回答并展示完整引用来源。

**架构：** Nest 新增 `rag` / `knowledge` / `chat` 模块；向量在 Milvus，会话与文档元数据在 Postgres，题库仍以 Mongo 为真相源。前端 `packages/client/src/chat/` 提供三栏聊天 UI。流水线优先使用 LangChain（Loader / Splitter / Embeddings / Milvus VectorStore / Retriever / 流式 Chat）。

**技术栈：** NestJS、TypeORM、PostgreSQL、Milvus、`@langchain/openai`、`@langchain/community`、`@langchain/textsplitters`、`@zilliz/milvus2-sdk-node`、Vue 3、Ant Design Vue、Vitest、SSE。

## 全局约束

- 设计文档：`docs/superpowers/specs/2026-07-26-rag-chat-design.md`（已确认）。
- 题库索引字段以 Mongo schema 为准：`title`、`content`、`myNotes`、`aiAnswer`（设计中的「notes」即 `myNotes`）。
- 向量 collection 名固定：`interview_rag`；metadata 必含 `sourceType`（`question` | `document`）、`sourceId`、`title`、`chunkIndex`。
- 上传知识库文件上限：**10MB**；类型：`.md` / `.txt` / `.pdf` / `.docx`。
- 多轮上下文：最近 **10** 轮消息。
- Embedding 默认模型：`text-embedding-v3`（可用 `AI_EMBEDDING_MODEL` 覆盖）。
- 聊天/上传限流：约 **10 次 / 60 秒**（对齐现有 AI 端点）。
- UI 文案中文；不引入多用户鉴权。
- 纯函数优先 TDD；服务端新增 Vitest（当前 server 无测试运行器）。
- 中文注释与用户可见文案；提交信息可用英文 conventional commits。

- [ ] **步骤 6：实现 `citations.ts`**

```ts
import type { ChatSourceRef } from './entities/chat-message.entity';

type Retrieved = {
  pageContent: string;
  metadata: Record<string, unknown>;
  score?: number;
};

function asString(v: unknown, fallback = ''): string {
  return typeof v === 'string' ? v : fallback;
}

export function docsToSources(docs: Retrieved[]): ChatSourceRef[] {
  const out: ChatSourceRef[] = [];
  const seen = new Set<string>();
  for (const doc of docs) {
    const sourceType = asString(doc.metadata.sourceType) as ChatSourceRef['sourceType'];
    const id = asString(doc.metadata.sourceId);
    if (sourceType !== 'question' && sourceType !== 'document') continue;
    if (!id) continue;
    const key = `${sourceType}:${id}`;
    if (seen.has(key)) continue;
    seen.add(key);
    const snippet = doc.pageContent.length > 240
      ? `${doc.pageContent.slice(0, 240)}…`
      : doc.pageContent;
    out.push({
      sourceType,
      id,
      title: asString(doc.metadata.title, id),
      snippet,
      score: doc.score,
    });
  }
  return out;
}
```

**接口：**
- `POST /api/chat/sessions/:id/messages`

  Response: `text/event-stream`  
  事件：`token` / `sources` / `done` / `error`

- [ ] **步骤 1：实现 `ChatRagService.streamAnswer`**

伪代码流程（须写成真实 TS）：

```ts
async streamAnswer(sessionId: string, content: string, res: Response) {
  // 1. 校验 session
  // 2. append user message
  // 3. recent = listRecentMessages(10)
  // 4. retrieved = await rag.retrieve(content, 6)
  // 5. sources = docsToSources(retrieved)
  // 6. system prompt 中文：仅依据检索与历史回答；无命中时声明「未命中知识库」
  // 7. 设置 SSE headers；foreach token -> event: token
  // 8. event: sources + data JSON
  // 9. append assistant message with full text + sources
  // 10. event: done
}
```

无命中时：`sources=[]`，system 仍要求模型可作一般性回答但必须说明未命中知识库。

限流：`@Throttle({ default: { limit: 10, ttl: 60000 } })`。

错误：捕获后 `event: error`，HTTP 尽量保持 200 + SSE（或在开始流之前可抛 503）。

- [ ] **步骤 2：Controller 接线**

使用 `@Res() res: Response`，调用 `streamAnswer`；DTO 校验 `content` 非空、`MaxLength(4000)`。

- [ ] **步骤 3：手工验收 SSE**
